A looped Transformer runs the same stack of <var>L</var> layers <var>N</var> times. It stores the parameters of only <var>L</var> layers but executes <var>N</var>×<var>L</var> of them. Prior work finds that looping helps models carry out multi-step reasoning, and in language modeling downstream accuracy rises with the loop count <var>N</var>, most strongly on reasoning tasks. Increasing <var>N</var> is therefore a natural way to scale a looped model.

As <var>N</var> grows, however, training becomes unstable and the best learning rate moves, so it has to be searched again for every <var>N</var>. Ouro, for example, reduced the loop count after observing loss spikes, and adopted a conservative learning rate because its compute budget did not allow a learning-rate sweep.

For width and depth, this problem already has an answer. μP and Depth-μP choose a parameterization under which the best hyperparameters stay put as the model gets wider or deeper, so they can be tuned on a small model and reused on a large one. We ask: <strong>can the loop count <var>N</var> do the same?</strong>

Our answer is <strong>Loop-μP</strong>: on top of the existing depth scaling, multiply each residual branch by 1/<var>N</var> and keep the learning rate independent of <var>N</var>. In our language-modeling experiments, the base learning rate tuned on the smallest model stays best for loop counts up to 8 and executed depths up to 384 layers. The key point is that <strong>loops cannot simply be treated as extra depth</strong>: all loops share the same weights, so the increments they write into the residual stream add along the same direction.

<h2 id="loops-vs-depth">Looping is not extra depth</h2>

Each branch of a residual network updates the residual stream as <var>x</var> ← <var>x</var> + <var>c</var>·<var>f</var>(<var>x</var>), where <var>c</var> is the branch multiplier. A deeper network adds more increments, so depthwise parameterizations shrink <var>c</var> as the depth <var>L</var> grows. Depth-μP uses <var>c</var> ∝ <var>L</var><sup>−1/2</sup> and CompleteP uses <var>c</var> ∝ <var>L</var><sup>−1</sup>, and both transfer the learning rate across depths.

A model of <var>L</var> layers looped <var>N</var> times executes <var>N</var>×<var>L</var> layers. Treating the loops as extra depth seems natural, which would multiply the branch by another <var>N</var><sup>−1/2</sup>. The catch is weight sharing. At initialization, <var>L</var> independent layers write increments in nearly unrelated directions, so like a random walk their sum grows only as √<var>L</var>. When one block is looped <var>N</var> times, every loop uses the same weights, the increments are positively correlated, and their sum grows linearly in <var>N</var>.

<LoopFigure id="vector-sum" language="en" />

Real Transformers behave the same way. We loop a 12-layer pre-norm Transformer stack <var>N</var> times and compare it with untied models that chain <var>m</var><sub><var>L</var></sub> independent 12-layer stacks (depth multiplier <var>m</var><sub><var>L</var></sub> = <var>L</var>/12), measuring the residual-stream norm at initialization. Without scaling, the looped norm grows linearly in <var>N</var>, while the untied norm grows only as √<var>m</var><sub><var>L</var></sub>. For the untied model, <var>m</var><sub><var>L</var></sub><sup>−1/2</sup> already keeps the norm of order one. For the looped model, <var>N</var><sup>−1/2</sup> is not enough and only <var>N</var><sup>−1</sup> works. <var>N</var><sup>−3/2</sup> also bounds the norm, but it drives the looped model toward the identity map.

<LoopFigure id="init-norm" language="en" />

The cosine similarity between increments explains the difference: the increments of 64 independent stacks are nearly orthogonal, whereas the 64 increments of a looped stack are all positively correlated, with a mean cosine of about 0.85.

<h2 id="derivation">Why exactly 1/N</h2>

The measurements in the previous section raise two natural questions. First, if the goal were merely to keep the initialized residual stream bounded, why not decay even faster, say as <var>N</var><sup>−3/2</sup>? Second—and more importantly for training—since the same weights are reused across all <var>N</var> loops and receive <var>N</var> gradient contributions on the backward pass, does the learning rate also need to be scaled with <var>N</var>?

This section works out both answers. Write the residual branch multiplier as <var>c</var><sub><var>N</var></sub> = <var>a</var><var>N</var><sup>−<var>α</var><sub><var>N</var></sub></sup> (where <var>a</var> is a constant independent of <var>N</var>), and write <var>N</var><sup>−<var>γ</var><sub><var>N</var></sub></sup> for how the step size of a single weight update scales with <var>N</var> (for Adam, which normalizes gradient magnitudes automatically, this is directly how the learning rate scales with <var>N</var>). We want to find the pair of exponents (<var>α</var><sub><var>N</var></sub>, <var>γ</var><sub><var>N</var></sub>).

Before diving into matrix algebra, we can summarize the entire argument in three lines. For a single learning rate to work across all loop counts <var>N</var>, the network must neither blow up nor stall as <var>N</var> grows:

- <strong>Step 1 (Stable forward pass at initialization)</strong>: Each loop writes an increment of size <var>c</var><sub><var>N</var></sub> into the residual stream. Because all loops share weights, the <var>N</var> increments add along the same direction, giving a total increment of size <var>N</var>·<var>c</var><sub><var>N</var></sub> ∝ <var>N</var><sup>1−<var>α</var><sub><var>N</var></sub></sup>. Keeping initialization from blowing up requires <strong><var>α</var><sub><var>N</var></sub> ≥ 1</strong>.
- <strong>Step 2 (Bounded feature update in a single loop)</strong>: One optimization step changes the weights by scale <var>N</var><sup>−<var>γ</var><sub><var>N</var></sub></sup>, so the branch output in a single loop changes by <var>N</var><sup>−<var>γ</var><sub><var>N</var></sub></sup>. Keeping feature updates from blowing up with <var>N</var> requires <strong><var>γ</var><sub><var>N</var></sub> ≥ 0</strong>.
- <strong>Step 3 (Order-one change in the final output)</strong>: The updated weights are reused in all <var>N</var> loops. In each loop, the residual branch (multiplied by <var>c</var><sub><var>N</var></sub>) nudges the final output in the loss-reducing direction by <var>c</var><sub><var>N</var></sub>·<var>N</var><sup>−<var>γ</var><sub><var>N</var></sub></sup>; summed over <var>N</var> aligned loops, the total output change is <var>N</var>·<var>c</var><sub><var>N</var></sub>·<var>N</var><sup>−<var>γ</var><sub><var>N</var></sub></sup> ∝ <var>N</var><sup>1−<var>α</var><sub><var>N</var></sub>−<var>γ</var><sub><var>N</var></sub></sup>. If this change grew with <var>N</var>, the optimal learning rate would have to shrink with <var>N</var>; if it vanished with <var>N</var>, training would stall unless the learning rate grew with <var>N</var>. Only when it stays of order one—requiring <strong><var>α</var><sub><var>N</var></sub> + <var>γ</var><sub><var>N</var></sub> = 1</strong>—does one learning rate suit every <var>N</var>.

Putting the three conditions together, Steps 2 and 3 give <var>α</var><sub><var>N</var></sub> = 1 − <var>γ</var><sub><var>N</var></sub> ≤ 1 (an upper bound from training), while Step 1 gives <var>α</var><sub><var>N</var></sub> ≥ 1 (a lower bound from the forward pass). The two bounds meet head-on, leaving the unique solution (<var>α</var><sub><var>N</var></sub>, <var>γ</var><sub><var>N</var></sub>) = (1, 0).

The figure below draws this ledger. Each line is a bar made of pieces, and the dashed line marks its length at <var>N</var> = 1. Set <var>c</var><sub><var>N</var></sub> = 1/<var>N</var>, keep the learning rate fixed, and change <var>N</var>: there are more pieces, each proportionally narrower, and all three bars stay on the dashed line. With any other branch multiplier or learning-rate scaling, at least one bar grows or shrinks with <var>N</var>.

Here <var>h</var><sup><var>r</var></sup> is the output of the branch matrix <var>W</var> in loop <var>r</var>, <var>x</var><sup><var>r</var></sup> is the residual stream after loop <var>r</var>, and the scalar output <var>f</var> is the standard inner product ⟨<var>V</var>, <var>x</var><sup><var>N</var></sup>⟩ = ∑<sub><var>i</var></sub><var>V</var><sub><var>i</var></sub><var>x</var><sub><var>i</var></sub><sup><var>N</var></sup>.

The initialization follows μP, which keeps each coordinate of a hidden vector of order one (written Θ(1)): each coordinate of <var>U</var> is about 1, each entry of <var>W</var> about 1/√<var>n</var>, and each coordinate of <var>V</var> about 1/<var>n</var>. We measure vector length by the root-mean-square (RMS) norm ‖<var>z</var>‖<sub>rms</sub> = √(⟨<var>z</var>, <var>z</var>⟩/<var>n</var>), the typical magnitude of a single coordinate.

Throughout, we take the large-width limit <var>n</var> → ∞ first, and then ask how each quantity scales as the loop count <var>N</var> grows.

<LoopDetails title="Full derivation: what each 1/n in the μP initialization does">

In a width-<var>n</var> network, we want <strong>each coordinate</strong> of an activation vector to stay of order one. Under μP initialization, each factor of 1/<var>n</var> has a specific job:

- <strong>Input vector <var>U</var></strong>: coordinates are independent 𝒩(0, 1), so each coordinate is about 1 and ‖<var>U</var>‖<sub>rms</sub> ≈ 1 (with inner product ⟨<var>U</var>, <var>U</var>⟩ ≈ <var>n</var>).
- <strong>Hidden matrix <var>W</var></strong>: entries are independent 𝒩(0, 1/<var>n</var>). Why variance 1/<var>n</var>? Because each coordinate (<var>W</var><var>U</var>)<sub><var>i</var></sub> = ∑<sub><var>j</var></sub><var>W</var><sub><var>ij</var></sub><var>U</var><sub><var>j</var></sub> sums <var>n</var> independent terms of variance 1/<var>n</var>, giving variance 1. Thus <strong>multiplying by <var>W</var> preserves the RMS length of a vector</strong>: ‖<var>W</var><var>U</var>‖<sub>rms</sub> ≈ 1.
- <strong>Readout vector <var>V</var></strong>: coordinates are independent 𝒩(0, 1/<var>n</var><sup>2</sup>), so each coordinate has size about 1/<var>n</var> (and ⟨<var>V</var>, <var>V</var>⟩ ≈ 1/<var>n</var>). The readout is this small because <var>f</var> = ∑<sub><var>i</var></sub><var>V</var><sub><var>i</var></sub><var>x</var><sub><var>i</var></sub><sup><var>N</var></sup> sums <var>n</var> coordinates: at initialization <var>V</var> is unrelated to <var>x</var><sup><var>N</var></sup> and the terms cancel to <var>f</var> ≈ 0; once training aligns the change of <var>x</var><sup><var>N</var></sup> with <var>V</var>, adding <var>n</var> aligned terms of size 1/<var>n</var> produces an order-one change in the output <var>f</var>.

</LoopDetails>

<strong>A key tool: at large width, each multiplication by <var>W</var> turns a vector to a new orthogonal direction.</strong> In the plane, multiplying a vector by a random matrix can send it in any direction and stretch or shrink it at will. At large width the picture is completely different: <var>W</var><var>U</var> almost always has the same length as <var>U</var> and is almost always orthogonal to it. The figure below draws 200 samples at each width: at <var>n</var> = 2 the samples scatter over the whole half-disc, and as <var>n</var> grows they collapse onto 90° and a length ratio of 1, with a spread that shrinks roughly as 1/√<var>n</var>. Multiplying by <var>W</var> once more gives <var>W</var><sup>2</sup><var>U</var>, again nearly orthogonal to both earlier vectors.

<LoopFigure id="orthogonal" language="en" />

Our derivation only needs three direct consequences of this fact:

- <strong>Distinct powers are pairwise orthogonal</strong>: <var>U</var>, <var>W</var><var>U</var>, <var>W</var><sup>2</sup><var>U</var>, … are pairwise orthogonal with RMS length tending to 1.
- <strong>Backward multiplications by <var>W</var><sup>⊤</sup> behave the same way</strong>: <var>V</var>, <var>W</var><sup>⊤</sup><var>V</var>, (<var>W</var><sup>⊤</sup>)<sup>2</sup><var>V</var>, … are also pairwise orthogonal, each with self-inner-product ⟨<var>V</var>, <var>V</var>⟩ ≈ 1/<var>n</var>.
- <strong>Products of distinct independent matrices are pairwise orthogonal</strong>: if layers have independent weights <var>W</var><sub>1</sub>, <var>W</var><sub>2</sub>, …, then <var>W</var><sub>1</sub><var>U</var> and <var>W</var><sub>2</sub><var>U</var> are orthogonal as well, each with RMS length tending to 1.

<LoopDetails title="Full derivation: why one multiplication by W gives an orthogonal direction">

The previous fold-out explains why the length is preserved: each coordinate (<var>W</var><var>U</var>)<sub><var>i</var></sub> sums <var>n</var> independent terms of variance 1/<var>n</var>. What about the direction? Look at the inner product ⟨<var>U</var>, <var>W</var><var>U</var>⟩ = ∑<sub><var>i</var>,<var>j</var></sub><var>U</var><sub><var>i</var></sub><var>W</var><sub><var>ij</var></sub><var>U</var><sub><var>j</var></sub>: it sums <var>n</var><sup>2</sup> uncorrelated terms of mean 0 and standard deviation 1/√<var>n</var>, which cancel down to order √<var>n</var>—negligible compared with the squared length ⟨<var>U</var>, <var>U</var>⟩ ≈ <var>n</var> (their cosine is about 1/√<var>n</var> → 0). In high dimensions, each multiplication by the random matrix <var>W</var> rotates the vector into a fresh direction orthogonal to the previous ones.

The rigorous random-matrix proof appears in Tensor Programs and the paper's appendix.

</LoopDetails>

<strong>Step 1 (Stable forward pass): shared weights make same-order terms add in length, requiring <var>α</var><sub><var>N</var></sub> ≥ 1.</strong> Each loop multiplies the residual stream by (<var>I</var> + <var>c</var><sub><var>N</var></sub><var>W</var>), so after <var>N</var> loops <var>x</var><sup><var>N</var></sup> = (<var>I</var> + <var>c</var><sub><var>N</var></sub><var>W</var>)<sup><var>N</var></sup><var>U</var>. When we expand the product, each loop either follows the identity trunk <var>I</var> or takes the residual branch <var>c</var><sub><var>N</var></sub><var>W</var>. There are 2<sup><var>N</var></sup> paths in total, and each path is one term of the expansion. The figure below lists all of them; click a path to see which term it gives.

Compare two layers (<var>N</var> = 2) with independent versus shared weights. There are two ways to take the residual branch once (the first-order terms, <var>m</var> = 1): take the branch in loop 1 and the trunk in loop 2, or vice versa. With independent weights (<var>W</var><sub>1</sub> and <var>W</var><sub>2</sub>), the two paths produce two <strong>orthogonal vectors</strong> <var>c</var><var>W</var><sub>1</sub><var>U</var> and <var>c</var><var>W</var><sub>2</sub><var>U</var>, whose combined length by Pythagoras is √2·<var>c</var>. With a shared weight <var>W</var>, both paths produce the <strong>exact same vector</strong> <var>c</var><var>W</var><var>U</var>, which adds in length to 2<var>c</var>. Across <var>N</var> loops, there are C(<var>N</var>, <var>m</var>) ways to choose <var>m</var> loops to take the branch. Under shared weights every one of them yields the same vector <var>c</var><sub><var>N</var></sub><sup><var>m</var></sup><var>W</var><sup><var>m</var></sup><var>U</var>, with combined length C(<var>N</var>, <var>m</var>)·<var>c</var><sub><var>N</var></sub><sup><var>m</var></sup>; under independent weights they yield C(<var>N</var>, <var>m</var>) mutually orthogonal vectors, with combined length only √C(<var>N</var>, <var>m</var>)·<var>c</var><sub><var>N</var></sub><sup><var>m</var></sup>.

This also explains Figure 3 algebraically: the increment <var>c</var><sub><var>N</var></sub><var>W</var><var>x</var><sup><var>r</var>−1</sup> written in loop <var>r</var> always starts with the same vector <var>c</var><sub><var>N</var></sub><var>W</var><var>U</var> and has positive coefficients on all higher powers, so increments from different loops are positively correlated.

The stability condition for the forward pass can be read off from the first-order term (<var>m</var> = 1). Being a single term of the expansion, it must stay bounded: that is a necessary condition. It is also sufficient, because the higher orders are controlled by the first one (C(<var>N</var>, <var>m</var>) is at most <var>N</var><sup><var>m</var></sup>/<var>m</var>!), so the total length is squeezed between two functions of the first-order term:

- <strong>Independent weights (depth)</strong>: the first-order term has length √<var>N</var>·<var>c</var><sub><var>N</var></sub>, and the squares of all orders sum to (1 + <var>c</var><sub><var>N</var></sub><sup>2</sup>)<sup><var>N</var></sup>, which lies between 1 + <var>N</var><var>c</var><sub><var>N</var></sub><sup>2</sup> and e<sup><var>N</var><var>c</var><sub><var>N</var></sub><sup>2</sup></sup>. The residual stream is therefore bounded if and only if √<var>N</var>·<var>c</var><sub><var>N</var></sub> is, that is, if the branch multiplier shrinks at least as fast as <var>N</var><sup>−1/2</sup>—which is why Depth-μP can use <var>L</var><sup>−1/2</sup>.
- <strong>Shared weights (loops)</strong>: the first-order term has length <var>N</var>·<var>c</var><sub><var>N</var></sub> = <var>a</var><var>N</var><sup>1−<var>α</var><sub><var>N</var></sub></sup>, and the total length lies between <var>N</var>·<var>c</var><sub><var>N</var></sub> and e<sup><var>N</var>·<var>c</var><sub><var>N</var></sub></sup>. If we still used <var>c</var><sub><var>N</var></sub> = <var>N</var><sup>−1/2</sup> (say <var>c</var><sub><var>N</var></sub> = 1/4 at <var>N</var> = 16), the first-order term would have length 1 for independent layers but 4 for shared loops, and including higher orders pushes the total length to about 15 (Figure 7). The residual stream is therefore bounded if and only if <var>N</var>·<var>c</var><sub><var>N</var></sub> is, that is, <strong><var>α</var><sub><var>N</var></sub> ≥ 1</strong>; the total length is then at most e<sup><var>a</var></sup> for any <var>N</var>.

If <var>α</var><sub><var>N</var></sub> > 1 (such as <var>N</var><sup>−3/2</sup>), then <var>N</var>·<var>c</var><sub><var>N</var></sub> → 0, every residual term vanishes as <var>N</var> grows, and <var>x</var><sup><var>N</var></sup> → <var>U</var>, collapsing the looped network to the identity map. The forward pass alone does not blow up, but the training analysis below rules it out.

<strong>Step 2 (One update step and feature change): why training stability requires <var>γ</var><sub><var>N</var></sub> ≥ 0.</strong> Now consider one gradient step. Let <var>ℓ</var>′ = ∂<var>ℓ</var>/∂<var>f</var> be the derivative of the loss with respect to the scalar output <var>f</var>, and let <var>b</var><sub><var>r</var></sub> = ∂<var>f</var>/∂<var>x</var><sup><var>r</var></sup> be the gradient of <var>f</var> with respect to the residual stream after loop <var>r</var>. Because <var>N</var> − <var>r</var> loops remain between <var>x</var><sup><var>r</var></sup> and <var>x</var><sup><var>N</var></sup>, backpropagation multiplies the readout vector <var>V</var> by (<var>I</var> + <var>c</var><sub><var>N</var></sub><var>W</var><sup>⊤</sup>)<sup><var>N</var>−<var>r</var></sup>; its zeroth-order term is <var>V</var>, so each coordinate of <var>b</var><sub><var>r</var></sub> has size about 1/<var>n</var>.

<h2 id="recipe">The Loop-μP recipe</h2>

A real looped Transformer combines depth <var>L</var> and loop count <var>N</var>: each loop runs a stack of <var>L</var> distinct layers with independent weights, and that entire <var>L</var>-layer stack is repeated <var>N</var> times with shared weights. Applying the conclusions of the previous section to each dimension:

- <strong>Loop dimension <var>N</var></strong>: repeating the stack <var>N</var> times adds constructively across loops, fixing the unique exponents <var>α</var><sub><var>N</var></sub> = 1 and <var>γ</var><sub><var>N</var></sub> = 0—multiply each residual branch by <var>N</var><sup>−1</sup> and keep the learning rate free of <var>N</var> (multiply by <var>N</var><sup>0</sup>).
- <strong>Depth dimension <var>L</var></strong>: within a single loop, the <var>L</var> independent layers add like a random walk as √<var>L</var>, allowing <var>α</var><sub><var>L</var></sub> ∈ [1/2, 1] with <var>γ</var><sub><var>L</var></sub> = 1 − <var>α</var><sub><var>L</var></sub>. As in Depth-μP, we ask the features of every layer within a loop to evolve as much as possible, which selects the left endpoint <var>α</var><sub><var>L</var></sub> = 1/2, <var>γ</var><sub><var>L</var></sub> = 1/2—multiply both the residual branch and the hidden-layer learning rate by <var>L</var><sup>−1/2</sup>.
- <strong>Width dimension <var>n</var></strong>: following standard μP, scale the hidden-layer Adam learning rate by <var>n</var><sup>−1</sup>.

<strong>Only <var>N</var><sup>−1</sup> keeps the best learning rate fixed across <var>N</var>.</strong> Under Loop-μP, the best base learning rate is 1.25×10<sup>−3</sup> for every <var>N</var> at <var>L</var> = 12, and the same holds at <var>L</var> = 24 and 48. <h2 id="conclusion">Conclusion</h2>

What separates looping from adding depth is weight sharing. Shared weights make the increments that every loop writes into the residual stream, and the changes caused by one update, add along the same direction instead of spreading over unrelated directions as independent layers do. The resulting Loop-μP multiplies each residual branch by 1/<var>N</var> on top of an existing depth parameterization and keeps the learning rate independent of <var>N</var>. In our language-modeling experiments, Loop-μP transfers the learning rate across loop counts (up to 8) and executed depths (up to 384 layers), and reaches a lower loss than loop factors that decay more slowly or faster than 1/<var>N</var>.

This work has limitations. Following Depth-μP, our theory analyzes a mean-centered MLP residual block and proves its results for linear networks; the extension to nonlinear activations and Adam relies on additional assumptions, and attention and normalization layers are not yet part of the analysis. Limited by compute, our largest model has 438M parameters and is trained on 10B tokens, and we leave larger scales to future work.

We hope Loop-μP offers the looped-model community a simple recipe for training better looped models at a lower tuning cost.
